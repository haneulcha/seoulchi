# 탐색 모드 설계 (2026-08-31)

선별(홈 12개)과 **동등한 지위**의 탐색 화면을 추가한다. 8주치 카탈로그를
카테고리·자치구·거리·요금으로 좁혀 보는 두 번째 경로다.

이 문서는 `2026-08-13-seoul-events-webapp-design.md`(웹앱 1차)를 대체하지 않고 확장한다.
홈과 상세의 기존 설계는 유효하다.

## 1. 무엇이 문제였나

화면에는 경로가 하나뿐이다. 이번 주 12개를 받아들이거나 떠나는 것 외에 할 수 있는 게 없다.
구체적으로 넷:

1. 이번 주 정보만 보인다 — **다가오는 행사를 기다릴 수 없다**
2. 날짜로 훑을 수 없다
3. 카테고리로 볼 수 없다
4. 요금·위치·카테고리로 좁힐 수 없다

`docs/2026-08-21-ui-ux-critique.md`가 같은 것을 다른 말로 적어 뒀다 —
휴리스틱 3(User Control and Freedom) **1/10**: "내비·검색·필터·정렬 전무",
휴리스틱 7(Flexibility and Efficiency) **1/10**: "데이터에 좌표와 파싱된 영업시간이 있는데
UI에는 지도도 '지금 열린 곳만'도 없음".

## 2. 결정 요약

| 항목 | 결정 | 근거 |
|---|---|---|
| 선별 vs 탐색 | **동등**. 루트 헤더의 세그먼트로 형제 | 사용자 결정. PRODUCT.md 포지셔닝 수정 필요 |
| 시간 범위 | **오늘 ~ +8주** | 예매·일정이 실제로 잡히는 범위. 이상치도 자연히 걸러짐 |
| 날짜 뷰 | **시간 축 목록** (격자 달력 아님) | 82%가 30일 이상 지속 — 달력 칸이 구분자 역할을 못 함 |
| 위치 | **거리 정렬 먼저**, 지도 타일은 보류 | 좌표 99.6%. `haversineKm` 이미 있음. 외부 의존성 0 유지 |
| 카테고리 | 원시값 55개 → **6그룹 + 기타** | 두 소스가 뒤섞여 `기타역사유적지` 같은 값이 그대로 노출 중 |
| 데이터 전달 | **슬림 인덱스 1개 + 클라이언트 필터** | 슬림 61KB gzip. 전체 필드는 200KB라 부담 |

## 3. 실측 근거

측정 시점: 2026-08-31, `data/meta.json`의 `weekKey`는 `2026-W35`,
`llmProvider`는 `rule`, 행사 272 · 장소 733.

**기간 분포가 달력을 기각한다.** W35 272건 중 30일 이상 지속 **224건(82%)**,
8~30일 38건, 1주 이내 **10건**. 격자 달력에 얹으면 거의 모든 날짜 칸이 같은 막대로 찬다.

**주간 파일이 대체로 중복이다.** W33·W34·W35 합집합 **384건**.
W35의 272건 중 **217건(80%)이 2주 전 W33에도 있던 같은 행사**. 주마다 새로 등장하는 건 37건.
주 단위 슬라이스는 이 데이터 성격과 맞지 않는다.

**미래 행사는 파일에 아예 없다.** `score`가 `startDate <= 주끝 && endDate >= 주시작`으로
자르기 때문에 W35 파일의 **미래 시작 행사는 0건**이다. "기다릴 수 없다"는 UI 문제가 아니라
데이터 문제이고, 원본은 이미 갖고 있다(서울시 19,497건 전량 수신).

**좌표는 충분하다.** 행사 271/272(99.6%), 장소 715/733(97.5%).

**영업시간은 부분적이다.** 장소 526/733(72%) 파싱 성공. 나머지 207건은 원문만 있다.

**요금 필터는 약하다.** W35 272건 중 `isFree` **211건(78%)**. 요금 텍스트가 있는 건 88건.
켜도 22%만 걸러진다 — 넣되 화면에서 확인하고 안 쓰면 뺀다.

**자치구는 24개**로 유효하나 칩으로는 안 된다.

**payload:**

| | raw | gzip |
|---|---|---|
| `data/events/2026-W35.json` (272건, 전체 필드) | 206KB | 39KB |
| `data/places.json` (733건, 전체 필드) | 837KB | 163KB |
| 슬림 인덱스 (1005건 = 272 + 733) | 240KB | **61KB** |

8주로 늘려 행사 ~700 + 장소 733 ≈ 1400건이면 **약 85KB gzip**으로 추정한다.

**이상치.** `endDate`가 `2626-08-08`인 항목이 있다. 원본 오타가 정규화를 통과했다.

## 4. 아키텍처

파이프라인 단계는 그대로다. `score` 뒤에 선택 경로가 하나 늘어난다.

```
fetch → hydrate → normalize → merge → score ─┬─ curate(LLM) ─→ 주간 파일 + curated  (기존, 홈용)
                                             └─ selectCatalog ─→ index.json         (신규, 탐색용)
```

**기존 파일은 하나도 건드리지 않는다.** 주간 파일·`curated`·`places.json`은 그대로고
홈이 계속 읽는다. 탐색은 새 파일만 읽는다. 두 화면이 서로 다른 파일을 읽는 것은 의도된 분리다 —
홈은 빌드 타임 SSG(클라이언트 데이터 0바이트)를 유지해야 하고, 탐색은 클라이언트 필터가 필요하다.

### selectCatalog

`selectCatalog(events, places, today, horizonWeeks = 8)` — 순수 함수.
`today`를 인자로 받는 프로젝트 관용구를 따른다(내부에서 `new Date()` 금지).

선정 조건: `startDate <= today + 8주 && endDate >= today`.
유효 시작일은 홈과 같은 `max(startDate, today)` 관용구를 쓴다.

**이상치 처리:** `endDate > today + 3년`이면 데이터 오류로 판정해 카탈로그에서 **제외**한다.
조건만 쓰면 `2626-08-08` 같은 항목이 목록 끝에 영원히 남는다.
조용히 버리지 않는다 — 배치가 해당 id와 원본 값을 stderr에 찍고
`meta.json`의 `anomalies`에 건수를 남긴다. ("실패를 숨기지 않음")

### 프리렌더 범위 확대

현재 `vite.config.ts`는 `crawlLinks: true`로 **홈이 링크하는 18개만** 프리렌더한다(스펙 10-5).
탐색이 1400건을 보여주므로 전량으로 넓힌다.

빌드 비용은 문제가 아니다 — Plan 2 실측 **페이지당 0.017초**이므로 1400페이지는 약 **+24초**다.

부수 효과: 크리틱 P1이었던 **"링크 안 된 id는 의도적 404"가 사라진다.**

## 5. 데이터 계약 — `data/index.json`

```json
{
  "generatedAt": "2026-08-31T21:55:57.203Z",
  "horizonEnd": "2026-10-26",
  "items": [
    { "id": "sc-1234", "kind": "event", "title": "…", "group": "전시",
      "district": "종로구", "place": "국립현대미술관",
      "lat": 37.58, "lng": 126.98, "isFree": true, "imageUrl": "…",
      "startDate": "2026-09-03", "endDate": "2026-11-30" },

    { "id": "vs-567", "kind": "place", "title": "…", "group": "공원·자연",
      "district": "성동구", "lat": 37.54, "lng": 127.04,
      "hours": { "open": "09:00", "close": "18:00", "closedWeekdays": [1] } }

```

목록·필터·거리에 필요한 필드만 담는다. 상세 정보는 SSG된 상세 페이지가 갖는다.

장소의 `hours`를 포함한다(526건). `open-now.ts`가 이미 있으므로 "지금 열림" 필터가 여기서 성립한다.
좌표가 없으면 필드를 **생략**한다(`0`으로 채우지 않는다 — 기존 규칙).

`emit`은 기존 규율대로 `catalogIndexSchema`(zod)로 **전부 검증한 뒤에** 쓰기 시작한다.

## 6. 카테고리 정규화 — `src/lib/category.ts` (신규)

원시값 55개(행사 18 + 장소 37) → 6그룹 + 기타.

| 그룹 | 행사 | 장소 | 합 |
|---|---:|---:|---:|
| 전시 | 168 | 152 | 320 |
| 체험·배움 | 129 | 118 | 247 |
| 공원·자연 | 0 | 196 | 196 |
| 역사·명소 | 0 | 191 | 191 |
| 축제 | 27 | 48 | 75 |
| 공연 | 51 | 24 | 75 |
| 기타 | 9 | 4 | 13 |

(3주 합집합 384 행사 + 장소 733 기준)

`공원·자연`과 `역사·명소`는 100% 장소다. `kind`가 이미 행사/장소를 가르므로
그룹은 두 번째 축으로 동작한다.

**미매핑은 던지지 않고 `기타`를 반환한다.** `LLM_PROVIDER` 규칙("알 수 없으면 던짐")과
다르게 가는 이유를 남긴다: 오타는 사람 실수라 즉시 깨뜨리는 게 맞지만, 서울시가 새 분류를
추가하는 건 정상적인 일이고 그때마다 배치가 죽으면 안 된다.
대신 미매핑 원시값을 수집해 stderr 경고 + `meta.json`의 `unmappedCategories`에 남긴다.

### 시간 축 그룹의 정의

시간 축은 필터가 아니라 목록의 골격이다. 그룹은 시간 순으로 넷:

1. `오늘 – 금요일` — 오늘이 토·일이면 생략
2. `이번 주말` — 이번 주 토·일
3. `다음 주` — 다음 월요일 ~ 일요일
4. 월별 — `9월`, `10월` … `horizonEnd`까지

**항목은 유효 시작일(`max(startDate, today)`)이 속한 그룹에 한 번만 놓는다.**
홈의 `effectiveStart`와 같은 관용구다. 결과가 중요하다 —
이미 진행 중인 장기 전시 224건은 전부 첫 그룹에 모이고, **뒤 그룹은 자연히
"그때 새로 시작하는 것"만 남는다.** 이게 "다가오는 행사를 기다린다"의 구현이다.
82%가 장기 전시라는 사실이 여기서는 문제가 아니라 정리 기준이 된다.

### 장소는 시간 축에 놓지 않는다

`Event`와 `Place`는 시간 의미가 다르다(AGENTS.md). 장소에는 시작일이 없으므로
시간 축 그룹에 넣을 수 없다. 목록 맨 아래에 별도 섹션으로 둔다:

```
│ 10월                            38건 ›│
├──────────────────────────────────────┤
│ 언제든 갈 수 있는 곳           733건  │  거리순(위치 있을 때) 또는 이름순
│  ┌───┐ 서울숲                        │
│  │IMG│ 성동 · 0.8km · 지금 열림      │
```

`가까운 순`을 켜면 시간 축이 사라지고 **행사와 장소가 거리 하나로 정렬된다.**
"여기서 뭐 하고 있지" 상황에서는 행사와 장소의 구분이 의미가 없기 때문이다.

**축의 우선순위를 데이터가 정한다.** `가까운 순`이 첫 줄에 있고 `자치구`가 셀렉트로 내려간 건,
"이미 밖에 나와 있는 상태에서 여기서 뭐 하고 있지"(PRODUCT.md 사용 맥락 2)에서
실제로 답이 되는 게 거리이기 때문이다.

**`기타` 13건은 칩에서 뺀다.** 칩 한 자리 값을 못 한다. 숨기는 게 아니라 `전체`에 그대로 있다.

**날짜는 상대 표현이 먼저다.** `오늘까지` · `9/3 시작` · `토·일`.
PRODUCT.md의 "절대 날짜보다 '오늘까지'가 앞선다"를 시간 축 안에서도 지킨다.

### 필터 상태는 URL search params

TanStack Router의 `validateSearch`를 zod로 쓴다(의존성 이미 있음).

이유는 공유가 아니라 **뒤로가기**다. 크리틱이 휴리스틱 3에 1점을 준 근거가
"12개를 받아들이거나 떠나거나"였는데, 필터를 만들면서 뒤로가기로 되돌릴 수 없게 하면
같은 점수를 다시 받는다.

## 8. 경계와 실패

크리틱이 1/10을 준 휴리스틱 9(Error Recovery)를 여기서 갚는다.

| 상황 | 처리 |
|---|---|
| 필터 결과 0건 | "조건에 맞는 게 없습니다" + **어떤 필터를 풀면 몇 건이 나오는지** 제시 |
| 위치 권한 거부 | `가까운 순` 비활성 + 사유 한 줄 + 자치구 셀렉트로 유도 |
| `index.json` fetch 실패 | 명시적 에러 + 재시도. 빈 목록으로 위장하지 않는다 |
| 로딩 | 껍데기가 SSG라 세그먼트·칩은 즉시 뜨고 목록만 스켈레톤 |
| `hours` 파싱 실패 207건 | `지금 열림`이 이들을 **버리지 않고** "영업시간 미상"으로 남긴다 |

마지막 줄이 중요하다. 파싱 실패한 곳을 조용히 없애면 화면이 "안 열려 있다"고 거짓말한다.
기존 규칙("영업시간 파싱 실패 시 `null` + 원문 노출")의 필터 쪽 대응이다.
