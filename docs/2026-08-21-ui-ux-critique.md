# 웹앱 UI/UX 진단 (2026-08-21)

홈(`/`)과 상세(`/e/$id`) 두 화면에 대한 디자인 크리틱입니다.
Plan 2(웹앱 1차) 완료 시점의 화면을 실측했고, **다음에 무엇을 고칠지 정하는 근거**로 씁니다.

## 어떻게 측정했나

계획 문서들과 달리 이 문서는 코드가 아니라 **실행된 화면**을 근거로 합니다.

```bash
npm run build                          # dist/client 생성
ln -s dist/client <tmp>/seoulchi       # base가 /seoulchi/라 경로를 맞춰준다
python3 -m http.server 4173            # <tmp>에서 정적 서빙
# → http://localhost:4173/seoulchi/
```

- Playwright로 390×844(모바일)·1440×900(데스크톱) 스크린샷과 DOM 계측
- 대비비는 페이지 안에서 계산했습니다(Tailwind v4가 `oklch()`를 내보내므로
  canvas로 실제 렌더 RGB를 읽어야 정확합니다)
- `impeccable`의 `detect.mjs`로 결정론적 안티패턴 스캔

측정 시점의 상태: `data/meta.json`의 `weekKey`는 `2026-W33`,
`updatedAt`은 `2026-08-14T10:59:22Z`, 오늘은 `2026-08-21`입니다.
**배치가 한 번도 안 돌아 데이터가 한 주 묵은 상태**이고, 진단 P0 중 하나가 여기서 나옵니다.

## Anti-Patterns Verdict

**LLM 판정: AI가 만든 것처럼 보이지 않습니다 — 대신 "아무도 디자인하지 않은" 것처럼 보입니다.**

Impeccable 절대 금지 목록은 하나도 걸리지 않았습니다. 그라디언트 텍스트 없음, 유리질 카드 없음,
섹션마다 대문자 eyebrow 없음, 사이드 스트라이프 없음, hero-metric 템플릿 없음. 드문 일입니다.

문제는 반대쪽입니다. 앱 전체의 색은 `bg-white text-gray-900` + 요금 초록 하나이고,
서체는 시스템 기본, 간격은 Tailwind 스케일 그대로입니다. **의도적으로 내린 시각적 결정이 한 건도 없습니다.**
역설적으로 앱에서 유일한 색채 사건은 이미지 로드 실패 시 나오는 8색 폴백 블록인데,
그건 사고이지 디자인이 아닙니다. 지금 이 화면을 보고 나올 반응은 "AI가 만들었네"가 아니라
"개발자가 오후에 붙였네"입니다.

**결정론적 스캔** (`detect.mjs`, `dist/client`): 8건 — 전부 오탐으로 판정.
- `gray-on-color` 6건 (`app-2GT6nCPc.css:2`, `_id-BQuk2yls.js:1`): 미니파이된 Tailwind 번들 한 줄에
  `text-gray-*`와 `bg-green-100`이 같이 등장해서 잡힌 것. 실제 조합은 `OpenNowBadge`의
  `bg-green-100 + text-green-800` 하나뿐이고 이건 정상입니다.
- `numbered-section-markers` 2건 (`index.html`, "09, 10, 11" / "10, 11, 12"): 행사 날짜 범위 텍스트입니다.
- `src/` 직접 스캔은 0건(exit 0).

**시각 오버레이**: 주입하지 않았습니다. Playwright로 스크린샷과 DOM 계측을 직접 수행했고
`live-server.mjs` 오버레이 경로는 쓰지 않았습니다 — 사용자에게 보이는 오버레이는 없습니다.

## Overall Impression

배치 파이프라인의 규율이 화면까지 이어지지 않았습니다. `AGENTS.md`의 규칙표
(좌표 없으면 필드 생략, 파싱 실패 시 원문 노출, 화면은 절대 비지 않는다)는 **데이터가 거짓말하지 않게 하는** 규율인데,
정작 화면은 **데이터를 이해 가능하게 만드는** 일을 아직 하지 않고 있습니다.
원본 API의 어휘가 그대로 사용자에게 도달합니다.

가장 큰 기회 하나: **"이번 주"라고 말해놓고 시간을 보여주지 않는 것.**
이 앱의 존재 이유는 "지금/이번 주에 뭐하지"인데, 화면의 시간 정보는 전부 절대 날짜 범위입니다.
`2/24(화) – 8/20(목)`은 "내일 끝난다"를 숨깁니다. 데이터에는 `today`가 이미 들어와 있고
`formatDateRange`도 `today`를 인자로 받습니다 — 표현만 바꾸면 됩니다.

## What's Working

1. **정직함이 코드 수준의 원칙으로 박혀 있습니다.** `Fact`는 값이 없으면 줄을 통째로 접고,
   `Fee`는 원문 우선에 없으면 생략하고, 영업시간 파싱이 실패하면 배지를 숨기고 원문(`useTime`)을 그대로 둡니다.
   빈 칸이나 "정보 없음"이 화면에 하나도 없습니다. 이건 대부분의 앱이 못 하는 일입니다.
2. **`OpenNowBadge`의 하이드레이션 처리가 정확합니다.** SSG에서 시간 의존 값을 서버 렌더에 넣지 않고
   effect 이후에만 나타나게 했습니다 — 정적 사이트에서 "지금"을 다루는 올바른 방법이고,
   그 이유가 주석에 적혀 있습니다.
3. **`pickHomeItems`의 폴백 설계.** 큐레이션 12개 중 2개만 생존해도 홈이 비지 않습니다.
   실측(2026-W33 픽 12개 중 8/18 시점 생존 2개)까지 주석에 남아 있습니다.
4. 모바일에서 가로 넘침 0(390px 뷰포트에서 `scrollWidth` 390), 최소 탭 타깃 64px — 둘 다 통과.

## Priority Issues

### [P0] 세로 포스터를 16:9·1:1로 뭉개 이미지가 정보가 아니라 노이즈가 됨
**계측**: 홈의 이미지 18개 중 14개가 세로 포스터(원본 종횡비 0.54~0.80)인데
큰 카드는 `aspect-video`(1.78), 컴팩트 행과 장소 카드는 `1.00` 박스에 `object-cover`로 넣습니다.
540×809 포스터가 358×201로 잘리면 세로의 약 25%만 남습니다.
**왜 문제인가**: 한국 공공 행사 포스터는 제목·날짜·장소가 이미지 안 텍스트로 들어 있습니다.
잘린 크롭은 그 텍스트를 반토막 내서 "읽을 수 없는 무늬"로 만듭니다.
64px 썸네일은 더 심해서, 컴팩트 행 9개의 썸네일은 정보 전달량이 0에 가깝습니다.
**Fix**: 큰 카드를 `aspect-[3/4]`로 바꾸거나(포스터를 포스터로 존중),
`object-cover` 대신 블러 처리한 같은 이미지를 배경으로 깔고 `object-contain`으로 전체를 보여주세요.
컴팩트 행의 64px 썸네일은 정보값이 없으니 아예 빼고 그 자리를 제목 두 줄에 주는 편이 낫습니다.
**Suggested command**: `/impeccable layout src/components/cards.tsx`

### [P0] 화면이 지난주를 "이번 주"라고 말하고 있음
**증거**: 오늘 2026-08-21. 헤더는 `이번 주 서울` / `8/10 – 8/16 기준` / `8/14 19:59 갱신`.
`meta.weekKey`가 `2026-W33`인데 오늘은 W34입니다. `AGENTS.md`대로 배치가 아직 한 번도 안 돌았기 때문입니다
(Actions Secrets 미등록). 화면에는 이 상태를 알리는 장치가 없습니다.
**왜 문제인가**: 이 앱이 파는 것은 최신성 하나입니다. 8/19에 끝난 도서관 강좌가
"이번 주 서울"로 떠 있으면 신뢰가 한 번에 무너집니다. 게다가 유일한 경고 신호인
`8/14 19:59 갱신`은 `text-gray-400` 12px, **대비 2.6:1로 WCAG AA(4.5:1) 실패** —
페이지에서 가장 중요한 신뢰 신호가 가장 안 읽히는 글자입니다(다른 텍스트는 전부 통과).
**Fix**: (1) `text-gray-400` → `text-gray-500`(4.84:1)로 올리고,
(2) `meta.weekKey`가 오늘의 주차와 다르면 헤더 문구를 `이번 주 서울`에서 실제 주차로 바꾸거나
"데이터가 N일 지났습니다" 배너를 띄우세요. `formatUpdatedAt`이 이미 `updatedAt`을 들고 있으니
경과일 계산은 한 줄입니다. 화면이 거짓말하지 않게 하는 건 이 프로젝트가 이미 채택한 원칙입니다.
**Suggested command**: `/impeccable harden src/routes/index.tsx`

### [P1] 이미지 폴백이 "에러"만 잡고 "영원히 안 옴"은 못 잡아 장소 카드 6개 중 4개가 흰 사각형
**계측**: 4초 대기 후에도 `naturalWidth === 0 && complete === false`인 이미지 4건,
전부 `api.visitseoul.net/comm/getImage`. 그리고 폴백 블록(`div[aria-hidden]`) 렌더 수는 **0**입니다.
**왜 문제인가**: `ItemImage`는 `onError`에만 반응합니다. 요청이 실패가 아니라 *대기*로 남으면
에러 이벤트가 오지 않아 폴백이 영원히 안 뜹니다. 결과적으로 "언제 가도 좋은 곳" 그리드의 2/3가
빈 흰 칸이고, 스펙 14장 #3이 설계한 안전망이 실제로는 작동하지 않습니다.
**Fix**: 카테고리 색을 `background-color`로 **처음부터** 깔고 그 위에 `<img>`를 얹으세요.
이미지가 뜨면 색을 덮고, 안 뜨면(에러든 무한 대기든) 색이 남습니다. `onError` 상태 관리 없이
한 줄로 두 경우를 다 덮습니다. 추가로 첫 화면 히어로 이미지의 `loading="lazy"`는 빼세요 — LCP를 늦춥니다.
**Suggested command**: `/impeccable harden src/components/ItemImage.tsx`

### [P1] 상세에 돌아갈 길이 없고, 홈에서 본 코멘트가 상세에서 사라짐
**증거**: `src/routes/e/$id.tsx`에 뒤로가기·홈 링크·헤더가 없습니다. 유일한 액션은 외부로 나가는 "원문 보기"입니다.

**왜 문제인가**: 상세는 공유 링크로 **직접 진입하는** 페이지입니다. 그때 사용자는 이 사이트가

코멘트 소실은 peak-end 실패입니다 — 사람을 클릭하게 만든 문장이 클릭 직후에 없어집니다.

**Suggested command**: `/impeccable craft 상세 페이지 헤더와 큐레이션 코멘트`

### [P2] 링크를 공유하면 아무것도 안 보임 — og 태그·페이지별 title 전무

> **이후 정정(2026-08-21, `impeccable init`)**: PRODUCT.md 인터뷰에서 사용자층이
> **"여전히 나 혼자 쓴다"**로 확정됐습니다. 공유 미리보기 카드는 명시적으로 범위 밖이므로
> 이 항목의 `og:`/`twitter:` 부분은 **P3로 강등**합니다.
> 다만 **페이지별 `<title>`**은 남습니다 — 탭을 여러 개 열었을 때 구분이 안 되는 건
> 혼자 쓰는 앱에서도 매주 겪는 불편입니다.

**증거**: `dist/client/index.html`과 상세 19페이지 전부 `og:` 0건, `twitter:` 0건,
`name="description"` 0건, canonical 0건, favicon 404. `<title>`은 19페이지 모두 동일한
`서울치 — 이번 주 서울`입니다.
**왜 문제인가**: "이번 주에 여기 갈래?"는 카카오톡으로 링크를 던지는 행위입니다.
지금 던지면 제목도 이미지도 설명도 없는 맨 URL이 갑니다. 이 앱의 주요 유통 경로가 막혀 있습니다.
탭 여러 개를 열면 전부 같은 제목이라 구분도 안 됩니다.
**Fix**: `$id.tsx`의 `Route`에 `head`를 추가해 `title`을 `{item.title} — 서울치`로,
`og:title`/`og:description`(장소·기간)/`og:image`(`item.imageUrl`)를 넣으세요.
`__root.tsx`가 이미 `head()`를 쓰고 있으니 패턴은 그대로입니다. favicon과 `theme-color`도 같이.
**Suggested command**: `/impeccable harden src/routes/e/$id.tsx`

### [P2] 데스크톱에서 1440px 중 576px만 씁니다

### 새로 발견된 이슈 (이번 재측정에서 처음 확인)

**[P1] 직접 URL 진입 시 카테고리 칩의 활성 표시가 실제 필터 상태와 어긋난다 (정적 서빙 특유의 하이드레이션 불일치)**

**증거**: `http://localhost:4173/seoulchi/browse?group=공연&free=true` 직접 로드(주소창 입력,
풀 페이지 로드) → 결과 목록은 **정확합니다**(193건 중 8건, 전부 무료·공연류 — 버스킹/콘서트).
그런데 카테고리 칩 줄은 "전체"가 `aria-pressed="true"` + 활성 스타일로 표시되고 "공연"은
`aria-pressed="false"`로 남습니다(1.5초 대기 후 재확인해도 지속, 새로고침 여러 번 재현).
클릭으로 같은 URL에 도달하면(먼저 `/browse` 무필터로 진입 후 칩을 순서대로 클릭) 문제가
재현되지 않습니다 — **주소창에 쿼리스트링을 직접 넣고 로드했을 때만** 나타납니다.
**원인 추정**: `/browse`는 SSG로 프리렌더되는데, 프리렌더는 항상 **빈 검색 파라미터** 상태로
한 번만 굽습니다(`dist/client/browse/index.html`을 직접 열어 확인 — `전체` 버튼에
`aria-pressed="true"`가 정적 HTML에 그대로 박혀 있음). 정적 서버는 쿼리스트링을 무시하고
항상 이 같은 파일을 돌려주므로, 브라우저는 "전체가 눌린" HTML을 받아 그 위에 하이드레이션합니다.
실제 필터링(`applyFilters`)은 `location.search`를 올바르게 읽어 정확히 동작하지만, 칩의
`aria-pressed`/활성 클래스는 하이드레이션 이후에도 교정되지 않고 남습니다 — 심지어 이후
**다른 필터로 클라이언트 내비게이션을 해도**, 값이 그대로인 칩(예: 이번 케이스의 `무료만`·
`지금 열림`)은 계속 잘못된 상태로 남는 것까지 확인했습니다(district만 바뀌는 완화 링크를
눌러도 `무료만`/`지금 열림` 칩은 여전히 "안 눌림"으로 표시, 실제 필터는 여전히 걸려 있음).
**왜 문제인가**: 사용자가 필터 URL을 북마크하거나 공유받아 직접 열면(브리프 Step 4 #5가
정확히 이 시나리오), 목록은 맞는데 "지금 뭐가 켜져 있지?"라는 화면의 말이 계속 거짓입니다 —
Heuristic 1(Visibility)·3(User Control) 둘 다에 걸리는 신뢰 문제입니다.
**고치지 않았습니다** — 태스크 제약상 코드는 건드리지 않고 보고만 합니다. `BrowseControls`의
`Chip active={search.group === g}`가 렌더마다 재계산되는데도 DOM에 반영 안 되는 것으로 보아
React 프로덕션 빌드의 하이드레이션 불일치 처리(마운트 시 mismatch를 감지해도 이후 값이
안 바뀌면 재적용하지 않는 경로) 쪽 원인일 가능성이 큽니다 — 정확한 진단에는 코드 조사가
더 필요합니다.

**[정보] 카탈로그 밖 진짜 존재하지 않는 id는 정적 호스트의 기본 404를 받는다**

기존에 알려진 사실은 아니었지만 심각도가 낮아 P 등급을 매기지 않았습니다: `/e/sc-nope`
같은 완전히 없는 id로 직접 진입하면 정적 서버(로컬은 `python3 -m http.server`, 배포는
GitHub Pages)의 기본 404가 뜨고 앱의 `NotFoundComponent`(현재 "홈으로" 링크 포함)는 아예
로드되지 않습니다 — 빌드 산출에 커스텀 `404.html`이 없기 때문입니다(GitHub Pages는 루트에
`404.html`이 있으면 그걸 씁니다만 이 프로젝트는 만들지 않습니다). 클라이언트 내비게이션으로
없는 경로에 도달하는 경우(앱을 쓰다가 깨진 내부 링크를 누르는 경우)만 앱의 `NotFoundComponent`가
뜹니다. 카탈로그 전량 프리렌더 이후로는 "존재하는 id인데 404"는 사라졌으므로 실무 영향은
작지만, 향후 공유 링크가 잘못 복사되는 경우 등에는 여전히 못생긴 호스트 기본 화면을 보게 됩니다.

2. **홈에는 묵은 데이터 장치가 없다 — 크리틱 원래 P0가 홈 얘기였는데 탐색만 정직해졌다.**

   뒤입니다")를 보여줍니다(`src/routes/browse.tsx` 확인). **홈(`src/routes/index.tsx`)에는
